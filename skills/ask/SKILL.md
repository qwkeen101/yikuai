# 追问

只问**当前块**还没定的事：边界条件、异常情况、规则细节，以及前面步骤留下的取舍。问到这一块没有未决问题为止。

先读 `${CLAUDE_PLUGIN_ROOT}/docs/flow-files.md` 和 `${CLAUDE_PLUGIN_ROOT}/docs/asking.md`，后者规定了每轮的格式和怎么处理回答。

## 步骤

1. **读这一块。** 读 blocks.md、本块 data.md、`docs/design/<NN-slug>/`、decisions.md、parked.md 里本块的条目、GLOSSARY.md 和相关 ADR。

   完成标准：知道这一块已经定了什么、搁置了什么。

2. **列未决。** 找出还没定的决定，写进 decisions.md「未决」，一行一条。逐项过一遍：data.md 每条状态流转、每条唯一性和删除规则、效果图每种状态，以及权限（谁能做）、并发（两人同时操作）、上限（数量、长度、时间）、失败和重试。「已定」和 parked.md 里已有的跳过；能查到的事实自己查。

   完成标准：「未决」列全了，里面每条都是要用户拿主意的决定。

3. **问一轮。** 从「未决」里挑这轮能问的（不取决于其它未答的题），最多 5 题，开头写「本块约剩 N 题」，N 是「未决」的条数。当前步骤记为「第 K 轮已发出」。

   完成标准：一轮问题已发出。

4. **记一轮。** 按回答处理，当场写文件：
   - 定下的：从「未决」移到「已定」。
   - 搁置的：从「未决」移进 parked.md。
   - 引出的新问题：加进「未决」。
   - 回答改变了结构或界面：改 data.md 和效果图。
   - 确定了新术语：写进 GLOSSARY.md。
   - 某个决定满足 ADR 的三条：写 ADR，并在「已定」那行的理由后注明 ADR 编号。

   完成标准：本轮每一题都已落到「已定」或 parked.md，文件已保存。

5. **循环或结束。** 「未决」不空就回到第 3 步。用户说「先这样」「够了」时，剩下的「未决」全部按推荐答案移进 parked.md。「未决」清空后，状态改为「规格」，告诉用户本块定了几条、搁置了几条，下一步运行 `/yikuai:spec`。

   完成标准：「未决」为空，状态是「规格」。
