# 看界面

先让用户看到界面再往下。产品不满意的地方在效果图上改，比在代码里返工便宜。只处理**当前块**。

先读 `${CLAUDE_PLUGIN_ROOT}/docs/flow-files.md`；向用户提问照 `${CLAUDE_PLUGIN_ROOT}/docs/asking.md`。

## 步骤

1. **对齐。** 读 blocks.md、本块 data.md 和 decisions.md。界面为「无」时：状态改为「追问」，当前步骤写「无界面，跳过看界面」，告诉用户下一步运行 `/yikuai:ask`，结束。有界面时，再看项目已有的界面：组件、样式变量、已有页面、`docs/design/` 里之前的稿，效果图沿用同样的风格。

   完成标准：列出本块要画的页面和弹窗，以及要沿用的样式来源。

2. **出图。** 每个页面一个自包含的 HTML 文件，写到 `docs/design/<NN-slug>/`，浏览器直接打开就能看。每个文件用页签切换四种状态：正常、空、加载、出错。移动端项目用手机尺寸的画框。示例数据贴近真实，字段取自 data.md。

   完成标准：清单里每个页面都有文件，每个文件四种状态齐全。

3. **核对数据。** 逐个检查界面上展示和输入的每个数据项，在 data.md 里找到对应字段。对不上的（缺字段、类型不对、需要新状态、需要新接口）列进「数据改动」。

   完成标准：每个数据项都对上了，或已列进「数据改动」。

4. **请用户看。** 告诉用户文件路径和每个页面的要点；有「数据改动」时按提问规矩一起问。用户提修改就改图再请他看。每轮定下的改动记进 decisions.md「已定」，数据改动当场写回 data.md。

   完成标准：用户确认效果图；data.md 和效果图一致。

5. **收尾。** 状态改为「追问」，告诉用户下一步运行 `/yikuai:ask`。
