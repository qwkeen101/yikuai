# spec.md 格式

~~~markdown
# 02 订单：规格

## 问题

从用户视角：现在遇到什么问题。

## 方案

从用户视角：做完以后是什么样。效果图见 `docs/design/02-orders/`。

## 用户故事

1. 作为顾客，我想取消还没发货的订单，以便买错时及时止损。
2. 作为运营，我想按取消原因统计订单，以便找出流失的主要原因。
3. ……

## 实现决定

- 数据：本块新增和扩展的实体、表，以及迁移方式。字段细节引用 data.md。
- 接口：引用 data.md 的接口契约，补充鉴权、分页、错误码等约定。
- 模块：要新建或改动的模块，以及它们之间的接口。
- 其它：decisions.md 里影响实现的决定。

## 测试决定

- 测什么：外部能观察到的行为，即接口的输入输出、页面上的结果。
- 在哪测：用到的测试入口，参照的已有同类测试。
- 关键用例：状态机每条流转、每条不变量、效果图里的空和出错状态。

## 假设

- P3 取消后库存立即释放（待确认）

## 范围外

- 部分退款：放到 05 块

## 任务

（任务存放在 GitHub Issues 时，按顺序列出 issue 链接）
~~~

## 规则

- 用户故事覆盖本块所有行为，编号连续。
- 实现决定写到模块和接口这一层。文件路径和代码片段很快会过时，留到实现时再定；状态机、类型形状这类写成代码比文字更准的，可以内联。
- 实体名、字段名和 data.md、GLOSSARY.md 一致。
- 「假设」每条带 parked.md 的编号，方便确认后回改。
