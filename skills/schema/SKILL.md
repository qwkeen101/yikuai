# 定结构

只处理**当前块**。数据结构先定，界面和细节都建立在它上面。这一步的关键是**防止表爆发**：能复用就复用，能扩展就扩展，新增要有理由。

先读 `${CLAUDE_PLUGIN_ROOT}/docs/flow-files.md`；向用户提问照 `${CLAUDE_PLUGIN_ROOT}/docs/asking.md`；data.md 格式见同目录 [DATA-FORMAT.md](DATA-FORMAT.md)。

## 步骤

1. **定当前块。** 读 `docs/flow/blocks.md`。有当前块就用它；没有就取下一个能开始设计的块，状态改为「定结构」。当前块已过「定结构」（后面步骤发现结构要改）时，状态保持不变，只处理要改的部分。

   完成标准：知道处理哪一块；新开始的块状态是「定结构」。

2. **盘点已有结构。** 读其它块的 `data.md`、`GLOSSARY.md`、相关 ADR，以及 blocks.md「现有结构」指向的代码（表、模型、类型、接口）。列出和本块范围相关的已有实体和字段。

   完成标准：本块范围里出现的每个名词，都查过有没有对应的已有实体。

3. **归类。** 本块用到的每个概念归为三类之一：**复用**（原样引用已有实体）、**扩展**（已有实体加字段、加状态或加类型值）、**新增**。每个「新增」写一句为什么不能复用或扩展。判断时参照：
   - 状态用一个字段加状态机表示，每种状态共用一张表。
   - 一对一的两样东西，通常是同一个实体。
   - 只为某个页面拼数据的，是查询或视图，不是实体。
   - 历史、日志、快照类的表，先确认确实有人要看。

   完成标准：每个概念都归了类，每个「新增」都有理由。

4. **定细节。** 按 DATA-FORMAT.md 写 data.md。拿不准的按提问规矩问，每轮回答后当场改 data.md，取舍记进 decisions.md「已定」。

   完成标准：每个实体都写齐 DATA-FORMAT.md 要求的各项。

5. **确认。** 用几行向用户总结：复用了什么、扩展了什么、新增了什么及原因，请用户确认。新术语写进 `GLOSSARY.md`。

   完成标准：用户确认。块原本在「定结构」时，状态改为「看界面」（界面为「无」时改为「追问」）。告诉用户下一步运行哪个技能。
