# 回看待确认

先读 `${CLAUDE_PLUGIN_ROOT}/docs/flow-files.md`；向用户提问照 `${CLAUDE_PLUGIN_ROOT}/docs/asking.md`。

## 步骤

1. **挑一批。** 读 parked.md「待确认」，取最多 5 条：用户指定了块就取那块的；否则先取已进入「实现中」或「完成」的块的（越晚确认越贵），再按编号从小到大。对每条，查它在哪些地方已被用上：data.md、spec.md「假设」、任务、已提交的代码（按编号和相关字段名搜）。

   完成标准：每条都知道暂按的答案和已经依赖它的地方。

2. **问。** 每条一题：问题、暂按的答案（作为推荐）、已经依赖它的地方。回「好」就是确认暂按的答案。

   完成标准：每条都有了回答；用户再次搁置的保留在「待确认」。

3. **落地。**
   - 确认的：移到「已处理」，在所属块 decisions.md「已定」补一行，spec.md 里对应的「假设」改写成正式决定。
   - 改了答案的：同样记录新结论，然后列出受影响的文件和任务。还没实现的部分，直接改 data.md、spec.md 和任务；已实现的部分，在所属块新建任务并写清依赖；所属块已「完成」时，按状态退回的规则改回「实现中」。改动大到需要重新设计时，告诉用户，建议退回到哪个状态，等用户定。

   完成标准：本批确认或改过的每条都在「已处理」；每条改了答案的都列出了影响，文件已更新或任务已建。

4. **汇报。** 告诉用户本批处理了几条、改了哪些文件、新建了哪些任务、还剩几条待确认，以及有没有任务需要运行 `/yikuai:build`。
